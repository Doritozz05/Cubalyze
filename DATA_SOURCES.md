# Data Sources & Attribution

This document records where CubeForge's data comes from, what we use, and how it
is regenerated. It exists so that every source is attributed and reproducible.

---

## 1. Algorithm database (`packages/algorithm-db`)

The algorithm catalog is generated by `pruebas/scripts/generate_seed_catalog.py`
from the fused dataset produced by `pruebas/scripts/fase5-fuse.ts`. It ships in
`packages/algorithm-db/src/seed/*.ts`.

### 1.1 SpeedCubeDB — primary source

- **Site:** https://speedcubedb.com
- **What we use:** the core algorithm sets — PLL, OLL, Basic F2L, Advanced F2L,
  COLL, WV, CLS, ELL, SV and Anti-PLL (~2,000 algorithms), including each
  algorithm's slot, move count, community votes and verification status.
- **Extraction:** `pruebas/scripts/scdb_parser.py` + `scdb_ajax_scraper.py`
  (public pages; raw HTML stays local in `pruebas/raw/`, gitignored).

### 1.2 BirdF2L — F2L dataset & taxonomy

- **Repo:** https://github.com/andydude/birdf2l (by andydude)
- **License of the dataset:** LGPL-3.0 (see the LICENSE shipped with the raw data)
- **What we use:** ~3,500 F2L algorithms and the **advanced F2L case taxonomy**
  (the two-letter case codes such as `Jb`, `Mi`, `Vb`, `Ti` and their canonical
  setups) used across the app.
- **Extraction:** `pruebas/scripts/download_birdf2l.sh` (gh-pages dataset).

### 1.3 Fusion rules (fase5-fuse.ts)

1. **SpeedCubeDB wins:** algorithms from the SCDB JSON are added first.
2. **BirdF2L fills gaps:** top algorithms per case, only if not already present
   and only if they actually solve the case (verified against the case setup).

Every algorithm must pass the verification test
(`packages/algorithm-db/src/__tests__/scdb-alg-verification.test.ts`) — if it
does not solve its case it is dropped, never shipped.

## 2. Reconstructions (`apps/web/public/reconstructions/`)

The Reconstructions view ships a static dataset (~14,565 solves) generated by
`pruebas/scripts/build-recon-web-data.ts`.

| Source | What we use | Attribution |
|---|---|---|
| **CubeRoot** (https://cuberoot.me) | Official/unofficial reconstructions (solve text, phases, stats, records) | Every record links back to the original solve page (`url`) |
| **reco.nz / reconz** | Community reconstructions with dates, steps and reconstructor credits | Every record credits the `reconstructor` (Brest, Stewy, …) |
| **WCA** (https://www.worldcubeassociation.org) | Competition names, WCA IDs and result metadata | Records link to the official competition page (`compWcaId`) |

**How it was collected:** public pages only (`/recon/*` from the official
`recon-sitemap.xml` for CubeRoot; `reco.nz/solve/{id}` pages). No API, no login,
no paywall, no bypass of technical measures. `robots.txt` was honored
(CubeRoot allows `/recon` with `Crawl-delay: 5`; reco.nz has no robots.txt).
Requests were rate-limited, jittered and single-threaded
(`pruebas/scripts/scrape_polite.py`). Raw HTML stays in `pruebas/raw/`
(gitignored); only derived, attributed data ships in the product.

## 6. Regeneration pipeline

```bash
# 1. Dump the current seed caseDefs (stable case IDs keep user progress intact)
pnpm --filter @cubeforge/algorithm-db exec vitest run src/__tests__/scdb-dump-seed-catalog.test.ts

# 2. Fuse SpeedCubeDB + BirdF2L
npx tsx pruebas/scripts/fase5-fuse.ts

# 3. Generate the seed TypeScript files
python pruebas/scripts/generate_seed_catalog.py

# 4. Rebuild reconstruction data (CubeRoot + reco.nz crawls)
pnpm dlx tsx pruebas/scripts/build-recon-web-data.ts

# 5. Verify
pnpm --filter @cubeforge/algorithm-db test
pnpm --filter @cubeforge/analysis-engine test
pnpm --filter @cubeforge/math-core test
```

## 7. Legal notes

- Move sequences are functional data; the community shares them openly. We
  attribute every source and link back to originals wherever possible.

  data) from it with attribution; if you redistribute derived datasets, review
  the BirdF2L license terms.
- The **WCA** and CubeRoot/reco.nz data we ship is public, aggregated, and
  attributed per record. If you plan a commercial use, contact the source
